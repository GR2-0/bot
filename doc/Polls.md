# Система опросов (Polls)

## Обзор

Система опросов позволяет администраторам создавать и проводить опросы среди пользователей бота через приватные сообщения. Опросы поддерживают два типа вопросов: с вариантами ответов и с текстовыми ответами.

## Архитектура

### Структура директорий

```
data/private/polls/
├── config/          # Конфигурации опросов
│   ├── poll_001.json
│   ├── poll_002.json
│   └── ...
└── results/         # Результаты опросов
    ├── poll_001_2025-01-15.json
    ├── poll_002_2025-01-16.json
    └── ...
```

### Команды бота

-   `/polls` - Управление опросами (только для админов)

## Конфигурация опроса

### Структура файла конфигурации

Каждый файл конфигурации опроса должен находиться в `data/private/polls/config/` и иметь формат `poll_XXX.json`, где XXX - уникальный ID опроса.

```json
{
    "id": "poll_001",
    "title": "Оценка митапа GR2.0",
    "description": "Помогите нам улучшить качество митапов",
    "target_audience": {
        "type": "meetup_attendees",
        "meetup_id": "53378e72-0772-468c-8d5a-6df033e23fbf"
    },
    "questions": [
        {
            "id": "q1",
            "type": "multiple_choice",
            "text": "Как вы оцениваете организацию митапа?",
            "options": ["Отлично", "Хорошо", "Удовлетворительно", "Плохо"],
            "required": true
        },
        {
            "id": "q2",
            "type": "text",
            "text": "Что можно улучшить в следующих митапах?",
            "max_length": 500,
            "required": false
        },
        {
            "id": "q3",
            "type": "single_choice",
            "text": "Будете ли вы участвовать в следующих митапах?",
            "options": [
                "Да, обязательно",
                "Скорее всего да",
                "Не знаю",
                "Скорее всего нет",
                "Нет"
            ],
            "required": true
        }
    ],
    "settings": {
        "anonymous": true,
        "allow_multiple_responses": false
    },
    "created_at": "2025-01-15T10:00:00+03:00",
    "created_by": "342122747"
}
```

### Описание полей конфигурации

#### Основные поля

-   `id` (string, обязательное) - Уникальный идентификатор опроса
-   `title` (string, обязательное) - Заголовок опроса
-   `description` (string, опциональное) - Описание опроса
-   `target_audience` (object, обязательное) - Целевая аудитория
-   `questions` (array, обязательное) - Список вопросов
-   `settings` (object, обязательное) - Настройки опроса
-   `created_at` (string, обязательное) - Дата создания (ISO 8601)
-   `created_by` (string, обязательное) - ID администратора-создателя

#### Поле target_audience

Определяет, кому будет отправлен опрос:

```json
{
    "type": "all_users", // Всем пользователям
    "meetup_id": null
}
```

или

```json
{
    "type": "meetup_attendees", // Только участникам конкретного митапа
    "meetup_id": "53378e72-0772-468c-8d5a-6df033e23fbf"
}
```

#### Типы вопросов

**1. single_choice** - Один вариант ответа

```json
{
    "id": "q1",
    "type": "single_choice",
    "text": "Ваш любимый язык программирования?",
    "options": ["Python", "JavaScript", "Java", "C++"],
    "required": true
}
```

**2. multiple_choice** - Несколько вариантов ответа

```json
{
    "id": "q2",
    "type": "multiple_choice",
    "text": "Какие технологии вас интересуют?",
    "options": ["AI/ML", "Web Development", "Mobile", "DevOps"],
    "required": true
}
```

**3. text** - Текстовый ответ

```json
{
    "id": "q3",
    "type": "text",
    "text": "Ваши предложения по улучшению:",
    "max_length": 1000,
    "required": false
}
```

#### Настройки опроса

-   `anonymous` (boolean) - Анонимный опрос (не сохранять user_id)
-   `allow_multiple_responses` (boolean) - Разрешить повторные ответы
-   Автоматическое завершение опросов отключено

## Логика работы

### 1. Создание опроса

1. Администратор создает JSON-файл конфигурации в `data/private/polls/config/`
2. Файл должен соответствовать схеме, описанной выше
3. ID опроса должен быть уникальным

### 2. Запуск опроса

1. Администратор отправляет команду `/polls`
2. Бот показывает список доступных конфигураций опросов
3. Администратор выбирает опрос для запуска
4. Бот определяет целевую аудиторию:
    - Если `target_audience.type = "all_users"` - отправляет всем пользователям из `users.json`
    - Если `target_audience.type = "meetup_attendees"` - отправляет только участникам указанного митапа из поля `attendees`
5. Бот отправляет опрос в приватные сообщения каждому пользователю
6. Создается файл результатов в `data/private/polls/results/`

### 3. Прохождение опроса пользователем

1. Пользователь получает сообщение с опросом
2. Для вопросов с вариантами ответов отображаются inline-кнопки
3. Для текстовых вопросов пользователь вводит ответ
4. Бот валидирует ответы согласно конфигурации
5. После завершения опроса результаты сохраняются

### 4. Завершение опроса

1. Администратор останавливает опрос вручную через команду `/polls`
2. Результаты финализируются и сохраняются

## Валидация конфигурации

### Обязательные поля

-   `id` - не пустой, уникальный
-   `title` - не пустой
-   `target_audience` - валидный объект с полем `type`
-   `questions` - не пустой массив
-   `created_at` - валидная дата ISO 8601
-   `created_by` - существующий ID администратора

### Валидация вопросов

-   `id` - уникальный в рамках опроса
-   `type` - один из: `single_choice`, `multiple_choice`, `text`
-   `text` - не пустой
-   `required` - boolean
-   Для вопросов с вариантами: `options` - не пустой массив
-   Для текстовых вопросов: `max_length` - положительное число

### Валидация целевой аудитории

-   `type` - один из: `all_users`, `meetup_attendees`
-   Если `type = "meetup_attendees"`, то `meetup_id` должен существовать в `meetups.json`

## Обработка ошибок

### Ошибки конфигурации

-   Некорректный JSON
-   Отсутствующие обязательные поля
-   Невалидные значения полей
-   Дублирующиеся ID вопросов
-   Несуществующий meetup_id

### Ошибки во время опроса

-   Пользователь не найден в целевой аудитории
-   Опрос истек
-   Невалидный ответ пользователя
-   Технические ошибки отправки сообщений

## Безопасность

-   Только администраторы могут создавать и запускать опросы
-   Валидация всех входных данных
-   Защита от SQL-инъекций (использование JSON)
-   Ограничение длины текстовых ответов
-   Проверка прав доступа к результатам

## Производительность

-   Асинхронная отправка сообщений
-   Батчинг для больших аудиторий
-   Кэширование конфигураций
-   Оптимизация запросов к базе данных

## Мониторинг

-   Логирование всех операций с опросами
-   Отслеживание статистики ответов
-   Мониторинг ошибок отправки
-   Алерты при критических ошибках
